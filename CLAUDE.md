# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Read this before touching code. It reflects real decisions made in real sessions, not defaults — don't second-guess them without flagging it to the human first.

## What this is

Relay is AI-assisted live presentation software for churches. It listens to a live sermon, detects scripture references (direct quotes and paraphrases), and routes the right content to multiple independently-styled output screens in real time. It is built to interoperate with OBS, ATEM and ProPresenter rather than replace them: OBS, vMix and kiosk screens over the local network, a projector or a switcher over HDMI. **NDI is parked and no ATEM accepts NDI in any case**, so HDMI, plus a converter on the SDI-only rack-mount ATEMs, is the whole switcher path (`docs/OUTPUT_ROUTING.md` §2).

Full context: `docs/SPEC.md` (canonical spec), `docs/DECISIONS.md` (why, not just what), `docs/RELAY_V1_AUDIT.md` (current health, the scorecards and the blocker list), `docs/qa/RELAY_GAP.md` (what a product-expansion brief asked for vs what actually exists, with the gap register and the two reversal proposals).

## Non-negotiable constraints

- **No native SDI hardware integration.** Ever, unless a human explicitly reopens this. HDMI output only, plus NDI if it is ever unparked. SDI setups are served by a **converter**: a small HDMI-to-SDI box takes Relay's plain display signal into any SDI chain, so nothing SDI-aware is needed in software. This line used to say "(ATEM, converters)" and the ATEM half was false: no ATEM ingests NDI at any tier, and a rack-mount ATEM has SDI inputs only, so the switcher is not the bridge. `docs/OUTPUT_ROUTING.md` §2 has the model-by-model detail. **The constraint itself does not move.**
- **Offline-first.** Every core feature (STT, verse detection, output rendering) must work with zero internet. Cloud STT is an optional fallback, never a requirement.
- **Operator override is a first-class control, never a fallback UI.** Always reachable in one action, at every stage.
- **Output channels are render targets of one shared template engine.** If you find yourself writing `if channel_type == "stage"` in rendering logic, stop — that's a template configuration problem, not a code problem.
- **Local-first data.** Transcripts, verse text, templates and service history live in local SQLite. Nothing leaves the device without an explicit, visible reason.

## Priority languages (STT)

Tier 1: **Yoruba, Swahili, Hausa**, plus English. Code-switching (English mixed mid-sentence with a local language) is the normal case, not an edge case — never write detection logic that assumes single-language input.

**Be honest about the moat**: today it is a hand-curated multilingual *reference-parsing* table (66 books × 3 languages, in `src-tauri/data/book_aliases.json`) on top of stock Whisper base. No fine-tuned acoustic model ships, no native speaker has reviewed the aliases, and word error rate has never been measured in any language. Yoruba numerals now parse (RG-126) and **that is not a claim about accuracy**: nobody has reviewed those words either, so the `yo` block in `src-tauri/data/**numerals**.json` is marked `unreviewed` (not `book_aliases.json` — this line named the wrong file, and an agent checking the cap would have found nothing and concluded it did not exist; enforced at `detection::parsed_an_unreviewed_numeral`, pinned by `languages.test.js`) and everything resolved through it is capped at `Suggest` and can never reach a wall unattended. `docs/LANGUAGES.md` says all of this plainly — **do not soften it.**

### Debugging audio / STT without a human at the mic

Every audio bug so far was invisible in the code and reproducible only with a specific mic in a specific room.

- `RELAY_RECORD_WAV=/path/x.wav` — write the CLEANED stream (what the VAD and whisper actually see) on Stop. Off by default, never uploaded. **Two things a pilot church must be told**, because this is the instruction that turns the moat from an assertion into a number: it **buffers the whole service in RAM** (48 kHz mono f32 ≈ **570 MB for 50 minutes**) and writes once, at Stop — so **press Stop, never force-quit**, or the recording is gone. A **second Start/Stop in the same run no longer overwrites the first**: the variable names one path and the capture thread used to truncate it every time, which turned 1837.8 s of a real service into a valid-looking 170.0 s file (F-11, RG-117). An existing file is never reused — the next free `-2`, `-3` … is taken and the `audio: wrote` line prints where the audio actually went. The hand-rolled RIFF header is pinned by `audio::gate::the_debug_recorder_writes_a_wav_that_can_be_read_back`; a single wrong field yields a file that opens as noise, after the service, with no second take.
- `RELAY_STT_TIMING=1`, `RELAY_AUDIO_RMS=1` — decode lag / what the voice gate sees. Content-free.
- `RELAY_SENTRY_DSN=…` — **debug builds only** — point crash reporting at your own Sentry project without touching Settings. Still scrubbed; compiled out of release. Empty = unset.
- `RELAY_KIOSK_ANY_ORIGIN=1` — **an operational escape hatch, not a debug flag.** The kiosk hub refuses a WebSocket handshake whose `Origin` is not one Relay served (DECISIONS §64, RG-108); a church hosting its own kiosk page on a Pi or a signage box needs this to keep connecting. The refusal names the variable in the line it prints, so the way out is in the same place as the problem.
- `RELAY_BENCH_WAV=… cargo test audio::gate stt::bench -- --ignored --nocapture` — replay real speech through the real front-end at any mic level (`RELAY_BENCH_SCALE`) and noise (`RELAY_BENCH_NOISE`). This is how the "deaf to a quiet preacher" bug was proved.

## Working conventions

- `rustfmt` + `clippy -D warnings` clean before any commit — CI enforces both.
- **No `unwrap()`/`expect()` in code that runs during a live service.** A panic mid-sermon is the worst possible failure. (Currently zero in the seven service modules; `main.rs` has 5, all startup-only.)
- Every module in `src-tauri/src/` has a doc comment stating its single responsibility. Keep it that way — don't let `router.rs` grow detection logic.
- **Never build an `OutputContent` or a `DetectionEvent` by hand.** Go through `pipeline::Fire`. Five hand-rolled copies drifted apart, and two silently dropped the scripture template.
- Confidence thresholds are configuration, not constants — and there is exactly ONE baseline: `Thresholds::default() == from_sensitivity(50)`, **by construction** (`router.rs`). Never introduce a second.
- Before implementing a feature, check `docs/DECISIONS.md`. If the decision isn't there, it hasn't been made. Ask, don't assume.
- **Measure before optimising.** `detection.rs` has an `#[ignore]`d benchmark showing the "obviously slow" 31k-verse semantic scan costs 2.6 ms/query at ~1 query/sec. It stays a linear scan. Beam search is benchmarked and deliberately NOT used.

1. **Never call `tick()` inside a reactive `$:` block** (Svelte) — re-enters the scheduler and infinite-loops the webview JS thread → hard freeze, no error. Use `afterUpdate`. **Pinned by `hardrules.test.js`.**
2. **Never hold a `Mutex` across `handle.emit` / `channels::broadcast_content`** — deadlocks the macOS main run loop against a command wanting the same lock. Compute under lock, release, THEN emit.
3. **The STT worker thread needs a big stack** (16MB via `thread::Builder`). `whisper_full()` is stack-hungry; the default 2MB overflows → silent SIGSEGV after the first transcript. **Pinned by `hardrules.test.js`.**
4. **Call `whisper_rs::install_logging_hooks()` once** — otherwise whisper.cpp floods stderr with thousands of lines per transcription.
5. **Audio capture start must be NON-BLOCKING, and a device that dies LATER must stop the loop.** `AudioEngine::start` spawns and returns; device errors come back via the `audio://error` event. **That sentence used to be true of start errors only** (RG-117): cpal reports a device unplugged mid-capture through the stream's error callback, and that callback was one `eprintln!`. The loop is `while !stop` around a 100 ms `recv_timeout` and the stream object stays alive, so the channel never disconnects — capture spun on a dead device for as long as the app was open, the transcript stopped mid-sermon with no banner, and because the debug recorder writes AFTER the loop exits, the recording was never written at all. `note_stream_error` now stores the reason, sets the stop flag, and the loop's exit path writes the recording FIRST and then returns the error into `on_error`. Pinned by `audio::tests::a_stream_error_stops_capture_and_keeps_its_reason` and `audioerror.test.js`.

7. **`initAudio()` runs at app level** (`App.svelte` onMount), not only in Settings — otherwise `$capture.available` is false on the default tab and every button looks dead.
8. **STT is fed the NON-overlapping tail of each chunk** — the detection chunker emits 50%-overlapping chunks; feeding them verbatim garbles whisper.
9. **Never hand-roll an app-data path.** Use `db::app_data_dir()`. A macOS-only `$HOME/…` variant meant packaged **Windows** never found the STT model and ran with speech recognition silently dead. Windows has no `HOME`.
10. **Only `DetectionMethod::Direct` may auto-fire — and "Direct" means Relay HEARD it, not that it parsed confidently.** A TF-IDF cosine is not a probability. Semantic/Ambiguous/**UncertainBook** are capped at `Suggest` in `router.rs::decide`, at any score. Do not "fix" this by raising a number. `UncertainBook` was added 2026-08-14 after a P0: `fuzzy_book` repairs a misheard book token by edit distance, gated only on "the next token is a number" — which is the exact shape of a church announcement. "please turn to **hymn number** three sixteen" put **Numbers 3:16** on the wall at 0.840 against a 0.50 bar, unattended; `room`→Romans, `row`, `van`, `day`→Daniel and 33 more did the same. The claimed mitigation ("marked FUZZY, costs confidence downstream") was worth **0.06** against a 0.34 margin. Its confidence was never wrong — it was a real parse confidence, about a word nobody said, which is why no threshold could have saved it. Two routes now yield `UncertainBook`: an edit-distance repair (never rescued — a guess about the acoustics), and an ordinary English word that is also a one-token alias (`song`, `job` — rescued by an explicit chapter/verse keyword, because the word genuinely *was* heard). **`psalm` is deliberately not on that list** and must never be: "Psalm twenty three" is how preachers say it. **Pinned by `router::semantic_can_never_auto_fire` and `router::corroboration_never_promotes_a_paraphrase`.**
11. **Panic keys live in `lib/shortcuts.js`, mounted once at `App.svelte`** — never per-view. `Space` means *advance*, app-wide, and nothing else. **With exactly one exception, added 2026-09-15 on the operator's decision: a FOCUSED BUTTON keeps its own activation.** Space is the platform's activation key for a `<button>`, and the typing guard only ever excluded text fields — so a keyboard operator who tabbed to `Rehearse`, `Blackout` or `Clear screens` and pressed Space advanced the programme instead of pressing the control under their finger, and `preventDefault` ate the button's own click. That is a key doing something other than what the focused control says it does, which is the shape this rule exists to stop rather than an application of it. **The exception is Space only.** `ArrowRight`/`PageDown`/`ArrowLeft`/`PageUp` are deliberately NOT narrowed and still drive the transport from anywhere, so the transport can never be lost — and `Esc` and `B` are untouched, because rule 15 outranks all of this. `isActivatable` asks about the ELEMENT (button, `role="button"`, `role="switch"`, a real link) and never about which view is mounted, so it cannot drift as surfaces are added; a **disabled** button activates nothing, so the transport keeps the key there. **Pinned by `shortcuts.test.js` — *"Space yields to a control that has focus"*, whose five cases include three that pass either way and exist to catch the opposite mistake (over-narrowing).**
12. **Audio levels are LEARNED, never assumed** (DECISIONS §19). Nothing may compare a signal to an absolute level. Three individually-reasonable thresholds together made Relay **deaf to a quiet preacher, silently** — 94% voiced at studio level, **2% at a church-laptop level**. Speech is *contrast*, not volume. Verify: `cargo test audio::gate -- --ignored`.
13. **Score STT changes through the DETECTOR, never by reading the transcript.** A grep-the-text scorer rated a hallucinated `Peter 8 verse 28` a success and a correct spelled-out reference a failure. The only question is *which verse would Relay put on the screen*.
14. **`persist_fire` takes the real `status`.** Manual fires are `'manual'`, never `'auto'` — the self-calibrating router learns from that column.
15. **A panic control may never report a success it did not achieve** (DECISIONS §20). `clear_screens`/`blackout` return `Result`; the frontend wrappers return a boolean **and** set the global `panicError` store — both, because panic controls fire from a global keydown handler and a shell button that must survive a crashed view, and neither can `catch`. `Live.svelte` once flashed "Screens cleared" over a `catch {}` that could never fire. **Pinned by `panic.test.js`.**
16. **`Esc` must not clear the screens while any dialog is open.** `shortcuts.js` checks for a mounted `[role="dialog"]`. Dismissing a help overlay or an arrangement picker is not a live action — it used to wipe the wall as a side-effect. **Pinned by `shortcuts.test.js` — *"Escape inside ANY open dialog does not clear the screens"*.** **And since 2026-09-21 the context keys stand down too** (RG-181): `A`, `D`, the arrows and Space ask the same `overlayOpen()` probe before touching the view, because with *Why this match?* open, `A` accepted the first claim rather than the one being read. `B` does not stand down; it is a panic key. 17. **macOS: the microphone dies on the FIRST correctly-signed build.** Notarization requires the hardened runtime; under it, opening an input device without `com.apple.security.device.audio-input` is TCC-killed, and without `NSMicrophoneUsageDescription` the app is *terminated the instant it asks*. `tauri dev` and unsigned pre-releases both work fine — so this is invisible until the one build you hand to a church. `src-tauri/relay.entitlements` + `src-tauri/Info.plist`, pinned by `models::config_boots`. **Do not "clean up" those files.** **Reproduce it locally without a certificate**: `npm run tauri build && ./scripts/sign-local.sh` — `codesign --options runtime` turns the hardened runtime on for an ad-hoc signature too, and the script fails loudly if the entitlement or the usage string is missing.
18. **The operator must see WHICH KIND of claim the AI is making** (DECISIONS §21). `matched_text` + `method` cross the IPC bridge and are rendered. A paraphrase shows **no percentage at all** — a cosine is not a probability, and a number that lies is worse than no number. Cyan for a guess, **never amethyst** (that means rehearsal) and never amber (that means ON AIR).

If they drift from the tag, `latest.json` stamps the new build with the OLD version, every install compares equal, and **nothing ever updates — silently**. Use `npm run version:set`; CI asserts agreement on every PR, the release gate asserts it equals the tag.
20. **Pre-release versions must be NUMERIC** (`0.1.0-1`, not `0.1.0-rc1`). Valid semver, builds a fine `.dmg` — and the Windows MSI bundler rejects a named identifier fifteen minutes into the release. `scripts/version.mjs` refuses it locally in a second.
21. **An empty env var is not an absent env var.** Passing `APPLE_ID`/`APPLE_TEAM_ID` as `''` on an unsigned build makes Tauri believe notarization was requested, and it dies on `Team ID must be at least 3 characters`. There is no way to conditionally omit a key from an Actions `env:` block, so they are exported to `$GITHUB_ENV` only when actually signing. (Same trap as the signing identity, one level deeper.)
22. **GitHub Actions evaluates `${{ }}` EVERYWHERE — including inside comments in a `run:` block.** An empty one is a parse error that invalidates the whole workflow, so GitHub can't even apply the `on:` filter and every push gets a zero-job "startup failure". Never write an Actions expression in a workflow comment, even to illustrate one.
23. **A release is signed per-platform, or not at all.** One global "is it signed?" flag *is* the bug: it tested `APPLE_CERTIFICATE` and shipped an unsigned Windows MSI in silence. Two certificates, two independent verdicts, and the gate fails loud on a real tag.
24. **The fire engine is generic over `tauri::Runtime`** (`fire_manual`, `handle_nav`, `clear_or_report`, `persist_cue`, `fire_media`, and `channels::{broadcast_content, clear, black, stage_next}`). That is what makes `e2e.rs` possible: welded to the concrete desktop runtime, the one path that puts scripture on a wall could not be driven without a window, and so was never tested. **Keep new fire-path code generic** — a concrete `AppHandle` quietly re-welds it. **Pinned by `hardrules.test.js`.**
25. **A migration must be RETRYABLE.** `ensure_manual_detection_status` rebuilds a table (SQLite cannot `ALTER` a `CHECK`). It had no `ROLLBACK`, so a mid-batch failure left the transaction open — the following `PRAGMA foreign_keys = ON` then ran *inside* it, where the pragma is a documented no-op, and the error panicked the app at startup with FKs off. The leftover `detections_new` scratch table then made **every subsequent boot** fail with "table already exists", forever, before the window is even shown. Always `DROP TABLE IF EXISTS` the scratch table first, and roll back on failure. **Pinned by `db::ensure_service_plans_is_retryable`.**
26. **`greet` is a COUNTER, not a health check — exactly one caller, forever.** It prints `console: webview up`, and on a machine that cannot screenshot the app that line is the only proof the webview loaded and reached the Tauri bridge. Its entire value is the *count*: one line, one console mount. The new-design branch added `probes.js:engine()` calling `greet` to ask "is the bridge attached?", and that probe runs from **both** the launch sequence and the Dashboard — so every launch printed the heartbeat **three times**. Nothing was broken, which is the point: the one instrument for diagnosing a blank console now read exactly like a webview reloading twice, and a real double-mount would have been invisible in the noise. **Liveness probes call `ping`** (silent, returns `true`). Pinned by `ipc.test.js`, which fails if any file other than `App.svelte` mentions `greet`.

27. **STT latency is a BUILD fact before it is a code fact, and the window is not the lever.** macOS links Metal unconditionally (`Cargo.toml`, macOS target block) because `default = []` shipped CPU-only builds that decoded the 8s window in **~1710ms against a ~1000ms budget** — slower than real time, so the transcript, the detection and the fire all ran seconds late and the backlog grew for as long as the preacher talked. Metal is **~602ms** on the same model (2.8x; medians of repeated runs — a first-ever build on cold caches measured 4193ms and that figure was wrong). Do not "optimise" `WINDOW_SECS`: 8s and 4s cost the same (whisper pads the mel window internally), and it is coupled to `router::DEFAULT_DEBOUNCE_MS`. `sysprobe::gpu_backends` must keep reporting Metal on macOS by TARGET, not by `cfg!(feature)` — a target dependency does not set the feature, and it reported CPU on a GPU build. Measure with `stt::decode_cost`; DECISIONS §36.
28. **Decoding more often mishears numbers, so the faster cadence and the corroboration rule are ONE change.** The cadence adapts to measured decode cost (`step_samples_for`, clamped 250–1000ms), and a shorter window decodes "Romans chapter eight verse twenty eight" as **Romans 8:16**, then **8:21**, before settling — complete, non-provisional, `Direct` misreads that `is_provisional` cannot catch. So `Router::decide_live` holds a reference from a PARTIAL window at `Suggest` until a second pass agrees. A FINAL window is exempt (no next pass is coming). The check runs BEFORE `decide`, because `decide` stamps the cooldown on `AutoFire` and a downgrade afterwards eats the real fire one step later. Suggestions are never gated. Never raise a threshold to "fix" a misread — that is rule 10 in a different costume.

29. **One window may inform the operator about several verses; it may put at most ONE on a wall.** `rank_for_wall` orders a window's candidates by `pipeline::better` and only the first may auto-fire — the rest are offered instantly. Found by watching a real service: 58 broadcasts in 45 minutes, with two fires sharing a timestamp to the tenth of a second (`Matthew 13:10` and `2 Chronicles 15:1` at 1194.2s). The debounce could not see it because it is keyed per REFERENCE and those are different references. A `whole_chapter` candidate is also dropped when the same window names a specific verse in that chapter — it is the first half of that reference, not a second one; a chapter named alone survives. DECISIONS §37.
30. **A stop-word between the chapter and the verse threw the verse away.** "chapter nine AND verse twenty-four" parsed as whole-chapter and fired **verse 1** at 0.88, unattended — 1 Corinthians 9:1, 2 Chronicles 15:1/26:1, Proverbs 3:1, Isaiah 61:1, Hebrews 6:1, Genesis 12:1, Psalms 23:1, all in one service. `is_ref_connector` skips `and`/`,`/`&` **only when a verse word follows**, so "Hebrews 12 and 13" stays two chapters. The corroboration rule (§36) cannot catch this class: it catches a decoder that wavers, and a deterministic parser is confidently wrong on every pass. When a phrasing misfires, diff it against the same sentence without the stop-word before touching a threshold.

31. **A zero backlog is not a low latency, and every instrument Relay had measured a PIECE.** The transcript was late while `stt::decode_cost`, the walk harness and the worker's own queue-depth log were all green, because none of them ran at the speed of speech — a pipeline permanently one cadence step + one decode + one corroboration pass behind the preacher reports a zero backlog for a whole service. `latency.rs` stamps nine named instants per decode pass on ONE monotonic clock and carries the trace id from the microphone to the projector; `stt::realtime::live_transcript_latency` is the only rig that feeds the real worker at wall-clock pace, and `Settings → Diagnostics` shows the same numbers on a packaged build. Four rules keep it honest: a stage never reached is an ABSENCE not a zero; the clock starts at the OLDEST audio still waiting (measuring from the freshest 200 ms lump moved the reported median from 349 ms to 158 ms with no code change); histogram tails are counted, never truncated; and **a gap with no voiced audio in it is silence, not cadence** (201 ms median vs 8604 ms worst when it leaked in). That fourth rule was narrower when it was written — *the gap after a **closed** utterance* — and the narrower version was correct and incomplete (RG-118). Silent chunks are appended to a window that has not closed, deliberately, because the pauses are part of the signal whisper needs; they accumulate toward the next step, so a decode fires having heard nobody and `is_final` is false the whole way through. Service 15 on 2026-09-06 recorded a **43480 ms** cadence sample exactly that way, `decode=3ms` on a `600ms` window with `voiced` unchanged across the gap. At 12663 samples it could not move a median, and it set `worst` and reached `p99` — the two numbers Diagnostics shows a church. The worker's own voiced count is what separates that from a real 43-second stall, and it is now passed to `transcript_emitted`. Pinned by `latency::tests::a_pause_inside_an_unclosed_utterance_is_not_counted_as_cadence`, and the older half must keep passing beside it. **Before optimising anything on this path, read the report — twice now the reflex answer was "STT is slow" and twice more than half of it was not.**

32. **The cadence floor must be a whole number of chunker hops, and the headroom must be 1.0.** `MIN_STEP_SAMPLES` was a flat 250 ms; audio arrives from `audio::Chunker` in `HOP_MS` (200 ms) lumps and in no other size, so it took TWO hops and the real cadence was 400 ms. A floor finer than the delivery granularity is unachievable; one between one hop and two costs two. `STEP_SAFETY` was 1.5 as "slack against a slow window" — the worker's loop already drains a batch whole and decodes it ONCE, so falling behind costs one decode however deep the queue and the slack was pure idle time. Together: **`ggml-base` 349 ms → 139 ms median, 2.43 → 4.74 updates/s, same binary, two constants.** The cost is duty cycle — a model slower than one hop now decodes continuously for a whole service, which is Stage F11's job to find. DECISIONS §38. **Those figures are `ggml-base` and the model is part of the number**: measured on one machine, `base` decodes in 59 ms and `small` in 152 ms — both inside ONE hop, so `small` is a better model at the same cadence — while `ggml-large-v3-turbo` takes 597 ms, which rounds to four hops and about **1.25 updates/s**. A church that chose `turbo` chose a quarter of the cadence and nothing told them. `docs/qa/audits/PERF-MODELS-2026-08-30.md`; Stage F11 answered for `turbo` in `audits/FIELD-2026-08-30.md`. **Pinned by `stt::adaptive_cadence::a_fast_decoder_steps_at_the_floor_not_at_a_fixed_second` — restoring `STEP_SAFETY = 1.5` or a floor finer than one hop both fail it.**

33. **The decoder decodes; nothing else runs on its thread — and every queue on the path is bounded and counts what it sheds.** `emit_detections` — semantic scan, three locks, a SQLite write, the Tauri emit, the kiosk fan-out — used to run inside the STT callback, between one decode and the worker's next `recv()`. Deciding what the LAST window said is not a prerequisite for decoding the next one. It runs on `relay-detect` behind a **bounded** queue: a full queue sheds a PARTIAL (the same window is decoded again in a moment) and blocks on a FINAL (which carries persistence and the spoken commands). Shed partials are COUNTED and shown — silent shedding is how a pipeline reaches "fine" while missing half its work. One consumer thread, so order is still exact.
    **Two corrections this rule needed, both found by the 2026-09-02 audit and closed on 2026-09-03.** *(a)* The sentence is absolute and the code is not: the STT callback still performs **one** `emit("stt://transcript")` before the hand-off, deliberately — the operator's eyes are the cheapest thing on the path and the only thing anyone is waiting on. That is the single named exception, it is documented at the call site, and it is not a licence for a second. *(b)* The boundedness described here was true of `main::DETECT_QUEUE` and of **nothing in front of it**: the capture callback → clean/chunk hop (`audio::CAPTURE_QUEUE`) and the chunk → whisper hop (`stt::STT_QUEUE`) were plain unbounded `mpsc::channel`s with no counter, so the handbook read as though the whole path was bounded when the first two thirds of it was not. An unbounded queue in front of a decoder does not prevent a backlog; it converts one into memory, and then into rule 31's failure — a transcript minutes behind a preacher while every instrument reads a zero backlog. Both are now `sync_channel` with a non-blocking `try_send` and `latency::note_dropped_audio()`, surfaced in Settings → Diagnostics as **audio dropped (never heard)**, which is worse news than a shed partial and is coloured accordingly. The capture callback may **never** block: stalling a device's real-time callback kills the capture stream outright. **Pinned by `hardrules.test.js` — *"rule 33 — no unbounded queue anywhere on the audio path"*, which also asserts that its own scanner can still see both queues.**

34. **Never make this path faster by making it less safe.** Rules 10, 28 and 30 all say a version of this and it keeps needing saying. The latency work moved no threshold, removed no corroboration, and did not let a partial reference fire. The corroboration delay shrank anyway — it costs exactly one cadence step, and the cadence got shorter. **Removing the wait in front of a safety rule is not the same as removing the rule**, and only one of the two is allowed.

35. **A status badge that cannot detect its own failure is not a status badge.** The original instance is CLOSED (RG-01/RG-02): Live's Output Status pane derived every per-channel badge from GLOBAL state (`$live && !$rehearsing && !$screenBlack`), so a kiosk browser source that had gone away still read **On Air** on the one surface an operator watches during a service. Live and the Outputs tab now decide from one backend fact through one shared, pure helper (`outputHealth.js::describeScreen`), and every output page reports that it is still painting. Liveness is still a *count* per template id — the hub records nothing about who connected, deliberately, and DECISIONS §35 is untouched.
    **The rule is the general one, and it keeps finding new instances.** 2026-09-03: **Settings → Updates** printed *"Update status · up to date"* whenever nothing was waiting — which was also what it said when no check had ever run, when the laptop was offline, and when the update manifest had been returning 404 since the day Relay was installed (RG-83). One reassuring sentence over four different situations, on the one path by which a fix reaches a church that already has Relay. `updater.js::updateChannel` records the outcome of the last check and `describeChannel` is the one place that turns it into words; a failed check still never interrupts an operator. **Pinned by `updatechannel.test.js`.**
    **The third instance is the sensitivity dial, 2026-09-17, and it is the one that governs what the AI may put on a wall unasked.** Five things in Rust move `Router::thresholds` — `apply_thresholds` (the dial and the two Settings sliders), `apply_profile` (a profile saved, a profile selected, a room applied) and `record_feedback` (the learning, on every confirm and dismiss) — and until that date not one of them announced anything; there was no `thresholds`-shaped event in the product at all. Live's dial was read once at `onMount` into a component-local `let`, on the one card the workspace router never rebuilds because the dock is mounted outside it, so the reading could not tell *"the engine says 50"* from *"nobody has asked the engine since launch"*. Three failures followed and all three were measured rather than argued: Settings moved the gate and Live showed the old number for the rest of the session; Live moved the gate and the next profile save SILENTLY REVERTED it, because `update_voice_profile` compares Settings' stale figure against an already-updated row, concludes the dial moved, and re-derives from it; and with nobody touching anything at all the router's own self-calibration drifted the dock stale. `detection://thresholds` carries the two thresholds and the dial position they map back to through `to_sensitivity`, the one inverse mapping, so no listener re-derives it and the two directions cannot drift. **The check is on the WRITERS, not on the emitters** — per rule 36, and because a guarantee kept on four of five doors is this repository's most-repeated bug — with `main`'s `setup` the one named exception, since it applies the learned gate before there is a webview to emit to. **Pinned by `hardrules.test.js`**, which fails on a sixth writer that does not announce and on any component that keeps its own copy of the dial.
    **The fourth instance is a picture that did not load, 2026-09-21 (RG-182).** Six media elements and no `on:error`, so a 404, an undecodable codec and a CSP refusal were one observable event, and `paintState` honestly read `content` because the DOM held a slide with a blank picture inside it: the beat said content, Relay believed content, and the desk printed On Air in amber over a blank frame. The renderer reports through one `onMediaError`, the page carries `media_error` on the beat it already sends, and `describeScreen` ranks that screen with `down` and names the URL. Pinned by `mediaerror.test.js` and `outputhealth.test.js`.
    When you add a status line, ask what it says when the thing behind it is broken — and if the answer is the same as when everything is fine, it is not a status line.

36. **The choke point is where the check goes, not the call sites.** `broadcast_with_clock` is the ONE caller of `channels::broadcast_content`, which is why the pre-air validator (`pipeline::preflight`, DECISIONS §42) lives there and covers the AI path, the manual box, spoken nav, plan cues, media, the emergency announcement and the countdown at once. A validator added at five call sites is a validator that will be missing from the sixth — four separate bugs in this repository have that exact shape. Same reasoning as rehearsal gating at the publishers (§18) and `pipeline::Fire` being the only way to build output. **It refuses only what is unambiguously broken and silently so** (a payload that would paint an empty screen; a template the output page cannot parse). It never checks that a screen is attached — a service runs on the console preview alone all the time — and the panic controls do not pass through it at all, because a validator that could refuse a blackout is a blackout that can fail. **Pinned by `hardrules.test.js`.**
37. **A fit loop with no notion of failure always succeeds, and that is the bug.** Forty rounds of ×0.95 will squeeze any verse into any box, so a template that had stopped working looked exactly like one that was working, at 2cqw. `TemplateRender` still shrinks and still shows the verse — blanking a screen is strictly worse for a congregation — but below **45% of the size the template's designer asked for** it reports, and Live says how small it went. The floor is a RATIO, not a point size: cqw is a share of the output's width, so a template designed at 6cqw makes a different claim from one at 3cqw. The console's program pane renders through the same component as the wall, which is what makes the measurement the wall's rather than a guess about it.

38. **Nothing a spoken control does may be invisible, and a passage may not outlive the content that replaced it.** The two defects `e2e.rs` carried as `#[ignore]`d tests, closed together because they are one failure in two coats (DECISIONS §54). **(a)** `ContextMemory.current` was written by every scripture fire and cleared by nothing, so a song, a notice or a countdown left the previous reading armed for the rest of the service and `nav("next")` walked it and answered `Fired` — true of the wall, false of the sermon. `ContextMemory::forget` is called from `broadcast_with_clock` for any non-scripture kind: the choke point, per rule 36, so a content kind added next year is disarmed by construction. **(b)** `handle_passage_nav` returned `bool`, which made the spoken in-passage jump the FOURTH door into the bug `NavResult` exists to prevent — "verse ninety nine" in a six-verse psalm moved nothing and said nothing. It now yields `NoPassage`/`NotInLibrary` and **announces its own outcome** through `announce_nav` rather than returning it to its one caller: reporting at the call site puts the guarantee on the door instead of in the room, which is exactly how the other three happened. **Pinned by `e2e::r2_a_passage_must_not_stay_armed_under_unrelated_content`.**

39. **An arrangement is a list of indices, so the ground can move under it.** `song_arrangements.sequence` stores section POSITIONS, not copied words — which is exactly right for a lyric edit (fix a typo in verse two and every arrangement still plays verse two, which is why the schema is shaped this way) and exactly wrong for a structural one. Reorder, insert, delete or rename a section and index 3 names a section nobody chose. **Relay does not guess which one was meant.** Each arrangement records `built_shape` — the song's `[[tag, label], …]` at build time, lyrics deliberately excluded — and anything built against a different shape is marked stale, shown as needing checking, and refused entry to a plan until a person has looked; saving it again IS the repair. The same guarantee is kept on the second door: a plan cue carries `arrangement_shape`, and `sync_song_in_plans` falls back to the song's own order rather than re-expanding through indices that moved, because the song's own order is always the right WORDS even when it is not the intended repeats. An empty `built_shape` is never called stale — that would be a claim from an absence, the same lie in the other direction. DECISIONS §55.

40. **Memory is what Relay has when the words do not say — when the words DO say, the words win.** A bare "verse 32" is resolved against `ContextMemory`, the passage last put on screen, and that is right for the case it was written for: a preacher walking Romans 8 who says "and verse eighteen". It is wrong the moment the sentence names its own book. **Found in a live service** (`docs/qa/audits/FIELD-2026-08-30.md`): the operator fired Proverbs 3:6 by hand, five minutes later the preacher said *"…going through in **Luke 10**. If you read from **verse 32**, 37"*, and **Proverbs 3:32 auto-fired at 0.88** with Luke 10 sitting in the same window. `detection::anchor_for_bare_verses` takes the LAST reference parsed from the window and a bare verse hangs on that; memory is the fallback, not the default, so "verse eighteen" with no book named still works exactly as before. **The first diagnosis of this was wrong** — the parser was blamed, a regression test was written against that theory, and it passed with the supposed fix reverted. A test that cannot fail is a theory that was never tested; the real path was `detect_bare_verses` → `resolve_bare_verse` → a hardcoded 0.88 and a hardcoded `Direct`. That label is still there and is still a lie (Relay inferred the book, it did not hear it) — left deliberately, recorded in the audit, because one service is not enough evidence to make every in-passage "verse eighteen" ask for a click.
    **The second half of this rule cost a second wrong verse** (F-8, `docs/qa/audits/FIELD-2026-09-06.md`; RG-115). *"The words do not say"* is not the same as *"the words did not parse"*: the preacher said *"is taken from **4th Peter chapter 5 verse 10**"*, there is no 4th Peter, so nothing parsed, `anchor` was `None` — and the bare `10` hung on `Psalms 92` from ten minutes earlier. **Psalms 92:10 at 0.88, unattended.** The window STATED a chapter and memory named a different one, and memory won. `detection::resolve_bare_verse_with_source` is now the ONE place this is decided: window anchor wins, a stated chapter with nothing parsed resolves to **nothing**, memory answers only when the words do not say. It **declines** rather than pairing the heard chapter with the remembered book, because that shows Psalms 5:10 — a different wrong verse, and rule 10 again. `detect_passage_nav` was never going to catch it: it caps at 8 tokens on purpose and that sentence is 9. Pinned by `detection::r4_audit::field_f8_a_chapter_this_window_states_is_not_one_memory_may_answer_for`, which was **verified by reverting the check** and watching it reproduce `Psalms 92:10` — the step this rule records as missing the first time.
    **The third half closed the label, on the second Sunday** (RG-179, DECISIONS §106, 2026-09-21). Service 24 on 2026-09-20: Psalms 55 on the wall by hand, the preacher quoting Hosea 6:1 with the book misheard, *"In verse 1 he says…"* — nothing parsed, no chapter stated, memory answered **Psalms 55:1 at 0.88, `Direct`, auto-fired**. The resolution was right by all three rules above; the label was the lie this rule had kept on purpose. `resolve_bare_verse_with_source` now says which rule answered and `DetectionMethod::for_bare_verse` labels a memory answer `UncertainBook`, so the router offers it and fires nothing; an anchor in the same breath is still `Direct`. The console prints *From memory* in cyan with no percentage. Pinned by `detection::field_2026_09_20` and `e2e::a_verse_answered_from_memory_is_offered_never_fired`, watched to reproduce the wall with the old label.

41. **Never use a native `confirm()`, `alert()` or `prompt()`.** Tauri's webview does not implement them — `confirm()` returns `false` without ever showing a dialog, so a two-step delete guarded by one deletes **nothing** and reports success, and `prompt()` blocks the webview's own event loop. Six files independently document this in comments; it was the one invariant that lived only in `docs/ARCHITECTURE.md` §8 and not here. Use an in-app two-step arm/confirm (`TemplateGallery`, `Settings`) or a mounted `[role="dialog"]`. Pinned by `hardrules.test.js`.

42. **A fit that measured the wrong typeface has to measure again — and it cannot find that out by looking for overflow.** A webfont is fetched only when something first USES it. An output page opens with nothing on it, so at mount `document.fonts.status` is already `loaded`, `TemplateRender`'s deferred re-fit hook is skipped, and the binary search then measures the FIRST verse of the service in the fallback face — which wraps into fewer lines and lets a larger size through. The real face lands a moment later and the text grows past the box it was fitted to. Measured on a fresh `output.html` at 1920×1080 with the default Classic Serif: Romans 8:28 settled at 110.9px and painted a **732px block inside a 583px `overflow:hidden` box**, first and last lines sliced through the middle, on the congregation's screen, until something happened to resize the window. Checking `overflowing()` straight after the fit does **not** catch it — the reflow the new face causes has not happened yet, so the box still reports that it fits. `document.fonts.check` is a fact available at that instant and that is what the rule asks; the retry is bounded to two, so rule 37's genuinely-unfittable case is still SHRUNK and reported through `onFit` rather than retried for ever. **Pinned by `templatefit.test.js`** (`needsRefit`), watched to fail against the pre-fix rule. RG-128.
43. **A screen that joins in the middle of a service is shown what is on the screens.** `run_kiosk_server`'s `hello` replied with the cached template and stopped there, so a client that connected after a fire got the NEXT fire and nothing before it: an OBS source restarting, a kiosk page reloading or a lobby TV dropping off the wifi came back **black** for the rest of the reading. `KioskHub` retains the last frame of the three kinds that decide what a screen is showing — `content`, `clear`, `black` — and sends it on hello, after the template. **It can never undo a panic control**, because `clear` and `black` are published through the same door and become the retained frame in their turn; and a rehearsal publishes nothing to this hub at all, so there is nothing of a rehearsal to replay. Two traps, both found the hard way: `stage_next` must NOT be retained (a monitor-only extra would stand in for the content it accompanies), and the matcher must not be a `starts_with` — `serde_json`'s map is a BTreeMap, so a content frame begins `{"content_kind":…` and the first version matched nothing while looking exactly like the bug it fixes. **Pinned by `channels::tests::{a_client_that_connects_mid_service_is_sent_what_is_on_the_screens, a_cleared_wall_stays_cleared_for_a_screen_that_joins_after_it, the_screen_frame_matcher_agrees_with_what_is_published}`.** DECISIONS §68. **Two more doors closed on 2026-09-21**: a client that LAGS past the broadcast buffer is handed `resync_frames` and counted (RG-195, `channels::tests::a_lagging_screen_is_counted_and_the_count_survives_a_beat`) rather than skipping frames in silence; and `output.html` replaces a socket unanswered for three beats and takes Relay's clock from `beat_ack` (RG-193, RG-194, `outputreconnect.test.js`), the two rules `Stage.svelte` had kept alone since §100.

44. **An overlay that disarms `Esc` must consume it — and must never paint over `Clear screens`.** Rule 15 and `panic.test.js` guarantee the panic control can never be *scrolled* out of reach. Nothing guaranteed it could not be *painted over*, and nothing guaranteed that `Esc`, once withheld from the shell, reached anybody. `shortcuts.js` stands down for a mounted `[role="dialog"|"alertdialog"|"menu"|"listbox"]` — correctly, per rule 16 — so mounting one TAKES the operator's panic key. **Four doors took it and gave nothing back**, found on one night by five agents on five different workspaces plus a browser pass. Two of the four took the button as well, and both were measured in a real layout engine rather than argued: with the **crash panel** up (`crash.js`, `inset:0`, opaque, `z-index:99999`), `elementFromPoint` over `Clear screens` returned the panel and `Esc` fired neither `clear_screens` nor `blackout` — under a message whose largest words read *"Your output screens are still live."* The **first-run wizard** did the same through `.fr-scrim` at `z-index:950` (neither `App.svelte` nor `Dock.svelte` sets a z-index at all), and `Settings → Run the setup walk-through` mounts it over a recorded service in one unguarded click. The **detection inspector** opens from Live *during* a service. The **four template menus** each carried a comment claiming *"Escape is handled globally — `shortcuts.js` gives Escape to any mounted `[role=menu]`"*; it does not, it RETURNS, and the stated reason for binding nothing (*"a handler would have to stopPropagation, which would swallow Space"*) does not follow — a handler that returns early for every key but `Esc` swallows nothing. **One press dismisses the overlay and nothing else; the second press is the operator's**, and by then the global handler has the key back. Conflating the two is the bug `shortcuts.js` already records against the cheatsheet. The only exemption is an overlay with **no shell behind it** — the four boot gates, which render before `App.svelte` and so take nothing away. **Pinned by `panicoverlay.test.js`**, which enumerates the whole tree rather than the overlays we happened to know about: a test that mounted the six known ones would have passed on the night all four were broken. Its own first version could not see `crash.js`, which sets its role with `setAttribute` — a scanner that quietly narrows passes everything.

## Detection notes

- `detection.rs` is DB/IO-free and heavily unit-tested. Book aliases: full names, numbered ("1 john"/"first john"/"1jn"), fast abbreviations ("ps 23 1"), ASR mishears ("sam"→Psalms).
- Spoken-number FSM: "three sixteen" → 3:16 (not 19). Single-chapter books ("Jude 4" → 1:4). Ambiguous "revelation 22" → suggests 22:1 AND 2:2.
- Voice/manual nav: "next"/"back" and the console Prev/Next both go through the `nav` command → `handle_nav`, which returns a **`NavResult`** (Fired / EndOfPassage / NoPassage / NotInLibrary). Not every outcome is a failure — reaching the end of a passage is a correct boundary, and the operator must be told *which*. It used to return `()` and silently do nothing.
- **A guarantee is only kept on the doors you checked.** This repository has had four separate bugs with one root cause: a rule enforced on one surface and skipped on its twin. Rehearsal gated three of four kiosk publishers. The throw-vs-swallow contract held for eight of nine group-1 wrappers. `NavResult` — built precisely so nav could never again silently do nothing — was thrown away by `remote_api` with `Ok(_)`, so the preacher's phone answered `{"ok":true}` at the end of a reading and moved nothing, which is the original bug verbatim. And the first-run wizard cleared its own `micOn` flag *before* awaiting `stopCapture`, so a failed stop left the flag reading "off" over a live microphone and the wizard opened a second capture on top of it (`firstrunmic.test.js`). When you fix something, **enumerate every caller of the thing you fixed**, and write the test on the surface that was missed.

## Ports (global registry, NN=03)

`5032` = operator console (Vite dev server) · `8031` = kiosk/OBS WebSocket hub · `8032` = embedded HTTP server (output/stage pages + `/media/<id>`).

**Two suites, and this file deliberately does not say how big they are.** Run them: `cd src-tauri && cargo test` and `npx vitest run` — **the runner's own summary line**, never a grep. The same three counts were corrected five times in one week and were wrong again each time, twice within a single day (RELAY_GAP §18); `docs/qa/QA_HARNESS.md` §0 is the one register that carries values, each beside the command that produces it. - **`qa.rs` owns the fixture. Do not write another one.** `qa::bare_app()` is a fresh install and nothing else — real schema, real seed, no operator has touched it — and `qa::{Wall, Kiosk, settle}` are the two doors out of the machine plus the drain. `e2e::app()` is now `bare_app()` **plus one documented difference** (a content-look override, without which its template assertion is vacuous), which is exactly the shape a deviation should have: three visible lines, not a fifty-line copy that drifts. A second fixture is how two suites start disagreeing about what a fresh install contains. `the_bare_fixture_is_a_first_launch_and_nothing_more` is the tripwire; it is what caught that `tpl_song` **is** seeded on purpose (every other built-in is scripture-shaped, so a lyric rendered through one showed the song title instead of the words).
- **The QA apparatus is documented, not folklore.** `docs/qa/QA_HARNESS.md` — Part 0 the current counts (each with the command that reproduces it), Part 1 the design and the five evidence layers, Part 2 the shared preamble every `relay-qa-*` agent inherits verbatim, Part 3 the roster, **Part 4 what is already pinned — read it before filing anything, so you don't "find" a fixed bug**. - **`vitest.config.js` MUST set `resolve: { conditions: ['browser'] }`. Do not "tidy" it away.** Svelte 4 maps its `.` export to `src/runtime/ssr.js` under every condition except `browser`, and that file defines `onMount`, `beforeUpdate` and `afterUpdate` as literal empty functions. `environment: 'jsdom'` does not imply the condition. Without the line, a component is compiled for the DOM and handed the SSR stubs: it mounts, it renders, and it silently skips every load-on-mount path — no list fetches, no subscription runs, and the test passes by doing nothing. It hid for the entire life of the project because the asymmetry is invisible: `svelte/internal` has only a `default` condition, so rendering, `onDestroy` and `tick` were always real, and only the mount half was dead. Guarded from three directions now — `r6-lifecycle-probe.test.js` asserts the runtime, `r2livepath.test.js` asserts that mounting the run column actually reaches `list_output_channels`, and `surface.test.js`'s `LIFECYCLE_LIVE` gate reads the runtime so its tests skip loudly rather than pass vacuously.
- **The frontend suite must pass on a CURRENT Node, and CI proves it on three.** Node ≥ 22 defines `localStorage`/`sessionStorage` on the global as own accessors that return `undefined` without `--localstorage-file`; vitest's jsdom environment leaves keys the global already owns, so Node's dead stub won and 66 tests in 6 files — every one covering what an operator sees on relaunch — failed on a clean checkout with `Cannot read properties of undefined`. `src/test-setup.js` hands the global a real jsdom Storage when the ambient one is missing. Don't delete it because "jsdom provides that". **CI now runs the frontend suite on Node 20, 22 and 24** — for a year it ran Node 20 only, so the shim protecting every other runtime was never once exercised, and deleting it would have left CI green over a checkout that fails for a contributor. Disabling it on a current Node fails **66 tests in 6 files**; on Node 20 it is a no-op, which is why one runtime could not see it.

- **`qa::bare_app()` manages `OutputHealth` and `ServiceLock` too.** A fixture without them is not a fresh install — it is an app in a state no church could be in, and a command reading either would panic rather than fail with a readable message.
- **The service record may never carry what a preacher said.** `service_events.detail` is a phrase Relay composes ("Main screen", the service title) and `perf_samples` stores percentiles, not traces — this is the part of the history most likely to be emailed to somebody. Pinned from both sides (`timeline_tests::nothing_a_preacher_said_reaches_the_timeline`, `timeline.test.js`) so a future column cannot quietly widen it.
- **`e2e.rs` is the one test that exercises what a congregation actually sees.** It drives the real commands (`manual_fire`, `nav`, `clear_screens`, `blackout`, `set_rehearsal`) against a real in-memory DB, through the real router and pipeline, and asserts on the events that leave the machine. Nothing is mocked but the window (`tauri::test::mock_builder`, dev-dependency `tauri/test`). **Add a test here whenever you touch the fire path.**
  - Use `mock_context(noop_assets())`, **not** `generate_context!()` — the real macro embeds `Info.plist` as a link symbol and expanding it twice fails with `_EMBED_INFO_PLIST is already defined`.
  - Template resolution reversed in **DECISIONS §29**: a SCREEN'S OWN template now WINS; a content-type default (a "content look") DEFERS to it, and a cue's deliberate choice is `template_pinned` and overrides. `resolveOutputTemplate(channelTpl, override, pinned)` is the one resolver; the console program pane and the Outputs inspector preview both call it so they cannot disagree with the wall.
  - A content-look default rides as an ID ONLY — it never serializes/broadcasts its template JSON, because it defers to per-screen. This is also a hard PERF rule: a default template carrying an embedded image (`data:` URL) can be MEGABYTES (one was 13 MB), and serializing + broadcasting that on every fire made verses take seconds. Only a PINNED cue template ships its JSON.

- **`stt::realtime::live_transcript_latency` is the ONE rig that runs at the speed of speech.** Every other benchmark in `stt.rs` measures a piece as fast as the machine can go, and the thing they are asked about — does the transcript keep up — only exists in real time. It feeds the REAL worker through `audio::chunks_as_captured` (the real chunker, the real voice gate) at wall-clock pace and reads `latency::report()`, so the number quoted in a decision and the number a church sees come from the same code. `RELAY_BENCH_WAV=… cargo test --release realtime -- --ignored --nocapture`. It cannot tell you word error rate, and there is no webview, output page or room in it.
- **`eval.rs` is a CI build gate**, not shipped code: a labelled corpus (`src-tauri/data/eval_corpus.json` — count it) scored **through the real router**, failing the build above SPEC's 5% wrong-verse rate. It measures detection over TEXT, not accuracy over AUDIO — WER has never been measured, in any language.
- **`ipc.test.js` is the contract test, in BOTH directions**: every Tauri command the frontend calls by string must exist in Rust, and every event Rust emits must be listened for. Renaming a `#[tauri::command]` otherwise fails silently inside a `catch {}` and a button just quietly stops working. **Its scanner has been wrong twice, and both times it looked exhaustive while checking less than it claimed** — first a regex that did not allow `_` (so `stt://language_unstable` and `output://panic_failed`, a *panic* path, were outside it), then a source list of `main.rs` alone (so `models.rs`'s four events and everything `channels.rs` emits were outside it). It now reads every `src-tauri/src/*.rs` — and, on the command side, **every `src/` file that imports the Tauri core rather than a hand-written list of four out of nine**. Tests guard both scanners, because a scanner that quietly narrows passes everything. A deliberately unconsumed event goes in `DELIBERATELY_UNHEARD` **with its reason**, and a test requires each entry to still be both emitted and unheard.
- **The documents are load-bearing, so their cross-references are tested.** `crossrefs.test.js` resolves every `DECISIONS §N` against the real headings and every `RG-` id against the register. **A citation that resolves to nothing is worse than an uncited claim** — the uncited one at least announces that it needs checking, while a dead `§16` looks like evidence. Four such references existed; a hand sweep found three and the test found the fourth on its first run. `relaygap.test.js` does the same for the register's own shape and its summary counts.
- **Test the bug, not the fix.** When fixing something, verify the new test FAILS if you reintroduce the original defect. Several tests in this repo were written that way on purpose; one entitlement test initially passed on a broken file because it grepped a comment.
- **A contract stated in a comment is not a contract.** Both of the gaps this line used to name were fixed by writing the rule down — `error.rs` for typed errors, the throw-vs-swallow groups at the top of `capture.js` — and for a while only one of the two was pinned by a test. **Both are pinned now.** `stopCapture` sat in the THROWS group, swallowing, for as long as the comment existed: one bare `catch {}` around both the bridge import and the command, so a `stop_capture` that failed on a poisoned audio lock printed "Start listening" over a live microphone and no caller's `catch` could fire. `micstop.test.js` pins it. When you place a wrapper in a group, add the test that holds it there.
- **A test's assertion surface is part of its claim.** `e2e.rs`'s `Wall` listens for Tauri events, so it can only ever see content that leaves through one of the two doors. `channels::stage_next` publishes to the kiosk hub and emits nothing — so the rehearsal guarantee was tested, passing, and false for the preacher's stage tablet the whole time. `nothing_reaches_the_stage_monitor_during_a_rehearsal` watches the hub itself. Anything new that publishes to the kiosk needs the same.
- Vitest gotcha: `beforeEach(() => invoke.mockReset())` returns the mock, and vitest treats a value returned from a hook as a **teardown function** — so it calls `invoke()` after every test. Use a block body.
